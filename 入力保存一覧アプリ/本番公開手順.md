# 本番公開手順(ランブック)

このセッションで実際に各回(第16〜23回)ごとに繰り返してきた、安全な本番反映の順番をまとめたもの。
新しい変更を本番に出すときは、この順番で進める。

## 1. stagingで確認する

1. 変更を`feature/*`ブランチで実装し、CI(`pytest`)が緑になることを確認する
2. `staging`ブランチへのPRを作り、CIが通ることを確認してからマージする
3. `staging`環境(Railway)へ自動デプロイされるのを待つ
4. Playwright等で実際にブラウザ操作し、変更が意図通り動くことを確認する

## 2. 本番の環境変数を確認する

本番(production環境)のStreamlitサービスに以下が正しく設定されているか確認する。

- `DATABASE_URL`(本番用Postgresへの参照)
- `RESEND_API_KEY` / `RESEND_FROM`
- `STRIPE_SECRET_KEY` / `STRIPE_PRICE_ID`(現在はテストモードのキー。Liveモードへ切り替える際は、
  Stripe側の事業者審査完了後に、Live用のキー・価格IDに入れ替える)
- `APP_BASE_URL`(本番URL)

## 3. 本番へデプロイする

1. `staging`から`main`へのPRを作り、CIが通ることを確認してからマージする
2. `main`ブランチへのマージで本番環境(Railway)へ自動デプロイされる

## 4. 独自ドメインを使う場合(今回は未実施)

現在は独自ドメインを持っていないため、Railwayが自動発行するドメイン(`*.up.railway.app`)を使用している。
これは最初からSSL(HTTPS)対応済みのため、追加作業は不要。

将来、独自ドメインを取得した場合は以下の手順で対応する。

1. Railwayの対象サービスでドメインを追加(`generate-domain`のカスタムドメイン版)
2. 表示されるDNSレコード(CNAME等)を、ドメインの管理画面に登録する
3. DNS反映を待ち、Railway側で証明書(SSL)が自動発行されるのを確認する
4. `APP_BASE_URL`環境変数を新しいドメインに更新する(メール内リンクやStripeのredirect先に影響するため)

## 5. 最初の1件を通す

本番URLに対して、実際に(自分 or テストアカウントで)以下を一通り確認する。

1. 新規登録 → 確認メールのリンクから認証 → ログイン
2. Freeプランの上限まで保存 → 上限到達のメッセージとアップグレード導線を確認
3. Stripeのテスト決済(テストモードの間はテストカード`4242 4242 4242 4242`)でPro化
4. Proプランで利用できることを確認
5. 確認が終わったテストアカウントは削除する
