# バックアップ手順

最終更新: 2026-09-12(第41課題で実地検証済み)

---

## 前提:今のバックアップ対象

本番Postgresには5つのテーブルがある。

| テーブル | 役割 | 現在の実データ件数 | 既存スクリプトの対象 |
|---|---|---|---|
| `schema_migrations` | 適用済みマイグレーション履歴 | 7件 | 対象外(コードから再生成可能) |
| `users` | ログインアカウント・課金情報(plan, stripe_customer_id等) | 1件 | ❌ 対象外 |
| `auth_tokens` | メール確認・パスワードリセット用トークン | 1件 | ❌ 対象外 |
| `memos` | メモ本体 | 1件 | ✅ `scripts/backup_db.py` |
| `audit_log` | 操作ログ・レート制限用の記録 | 0件 | ❌ 対象外 |

**今日分かった重要な事実**: 既存の`scripts/backup_db.py`は`memos`テーブルしかバックアップしていない。
実際に一番困るのは`users`(ログインできなくなる・課金情報を失う)の方なので、
本当の意味での「消えても戻せる」ためには、`users`と`auth_tokens`もバックアップ対象に含める必要がある。

---

## 手順(手動・現状)

### memosのバックアップ(既存)

```bash
railway ssh --service 入力保存一覧アプリ -- python scripts/backup_db.py
```

コンテナ内の`/tmp/memos_backup_<timestamp>.json`に保存される。標準出力にも全件JSONが表示されるので、
それをコピーして手元のPCにも保存しておく。

### usersのバックアップ(今回追加で確認した方法)

同じ仕組みで`users`テーブルも取り出せる。ローカルから本番Postgresへトンネルを張って直接実行する場合:

```bash
railway connect Postgres --tunnel-only --environment production
# 表示されたURLを DATABASE_URL に設定してから
python -c "
import os, json, psycopg
from psycopg.rows import dict_row
conn = psycopg.connect(os.environ['DATABASE_URL'], row_factory=dict_row)
rows = conn.execute('SELECT * FROM users').fetchall()
print(json.dumps([dict(r) for r in rows], default=str, ensure_ascii=False, indent=2))
"
```

※ `password_hash`(bcryptハッシュ)や`stripe_customer_id`が含まれるため、保存先・共有先には注意する。

### 復元

```bash
railway ssh --service 入力保存一覧アプリ -- python scripts/restore_db.py /tmp/memos_backup_xxxx.json
```

デフォルトは追記(既存データは消さない)。全消去してから復元する場合のみ`--replace`を付ける。
