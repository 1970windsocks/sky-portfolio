# ADR(Architecture Decision Records)

設計判断を「背景・検討した選択肢・決定・理由・トレードオフ」の形で記録する。
後から「なぜこうしたんだっけ?」に迷わないための記録。第68課題で導入。

## 一覧

| # | タイトル | ステータス |
|---|---|---|
| [0001](0001-in-process-email-queue.md) | メール送信の非同期化はインプロセスキューで行う | Accepted |

## 新しいADRを書くとき

- ファイル名: `NNNN-短いタイトル.md`(連番)
- 構成: ステータス・日付 / 背景 / 検討した選択肢(却下理由つき) / 決定 / 理由 / 結果・トレードオフ
- 「やらないと決めた」判断もADRの対象になる(例: 第67課題で見送ったDBロール分離)
