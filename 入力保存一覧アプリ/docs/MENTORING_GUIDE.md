# 伴走の言葉

第70課題で作成。答えをそのまま渡すと、その場では解決するが、次に似た問題に
出会ったとき同じようにつまずく。この70日間の「クロードコード部」で実際に
効果があった進め方(①②③に分解する、コピペ用プロンプトを渡しつつ本人に
実行してもらう、詰まったときの具体的な一言を用意する)を言葉にして残す。

## 基本の姿勢

- **答えを渡す前に、何を試したかを聞く**。「動きません」だけでは何も分からない。
  「どのコマンドを打って、何が表示されたか」を先に聞く。
- **選べる場面では、選ばせる**。「AとBどちらにしますか」を本人に決めてもらう
  場面を作ると、理解が「渡されたもの」ではなく「自分で選んだもの」になる。
- **トレードオフは隠さない**。「これで完璧です」ではなく「これには○○という
  制約が残っています」まで伝える方が、結果的に信頼される。

## 状況別のフレーズ

### 詰まっていそうなとき

- 「今どんな状態ですか? 出ているエラーメッセージをそのまま教えてください」
- 「それを試す前に、どうなると予想していましたか?」(予想と結果のズレに
  気づかせる)
- 「似たようなことを、前にどこかでやった記憶はありますか?」

### 大きすぎる問題で止まっているとき

- 「いきなり全部やろうとせず、まず1つだけ選ぶなら、どれにしますか?」
- 「`まず『入力→処理→出力』の1本道だけ作って』のように、最小の範囲に
  絞ってみましょう」(本講座の「詰まったら」セクションで繰り返し使われている型)

### 選択を本人にしてほしいとき

- 「選択肢はA・B・Cの3つです。それぞれの良い点・悪い点はこうです。
  どれを優先したいですか?」(第69課題の決め方テンプレートと同じ型)
- 「正解は無いので、今回あなたが一番大事にしたい基準は何ですか?」

### できたとき

- 「実際に動くところまで確認できましたね。次に似た問題が出たとき、
  今日やったことのどこが使えそうですか?」(その場の成功で終わらせず、
  次に転移できる形で振り返る)
- 結果だけでなく、**本人が自分で気づけた部分**を具体的に指摘して認める
  (「ここに自分で気づけたのが良かったです」)

## やらないこと

- 聞かれる前に全部のコードを書いて渡すこと(本人が考える前に答えを
  埋めてしまう)
- 「簡単です」「すぐできます」と難易度を決めつけること(人によって
  つまずくポイントは違う)
- できなかったことを否定的に評価すること(「なぜ分からなかったか」を
  一緒に分解する方が次につながる)
